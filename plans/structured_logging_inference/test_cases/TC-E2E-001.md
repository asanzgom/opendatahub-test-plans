# TC-E2E-001: End-to-end structured log emission and collection

**Objective**: Validate the full lifecycle from structured JSON log
emission by an inference component through the collection pipeline
to queryable storage in Loki.

**Preconditions**:
- OpenShift 4.16+ cluster with RHOAI 3.6 deployed
- LokiStack deployed via Loki Operator
- odh-observability controller running with logging enabled in
  Monitoring CR
- LLMInferenceService deployed with vLLM runtime in namespace
  `inference-e2e-ns` using model `granite-3b-instruct`
- Collection pipeline resources created (OTel or CLO path)

**Test Steps**:
1. Send an inference request to the vLLM endpoint with a W3C
   traceparent header:
   ```bash
   traceparent="00-$(openssl rand -hex 16)-$(openssl rand -hex 8)-01"
   curl -H "traceparent: $traceparent" \
     -H "Content-Type: application/json" \
     -d '{"model":"granite-3b-instruct","prompt":"Hello","max_tokens":10}' \
     http://<inference-endpoint>/v1/completions
   ```
2. Extract the `trace_id` from the traceparent header (characters
   4-35).
3. Wait 30 seconds for log ingestion into Loki.
4. Query Loki via the OpenShift Console Observe > Logs interface
   filtering by `trace_id`.
5. Verify log entries appear from vLLM with the matching `trace_id`.
6. Verify each log entry contains required OTel fields: `timestamp`,
   `severity`, `body`, `service.name`, `k8s.pod.name`,
   `k8s.namespace.name`.
7. Verify the log entry body contains inference request processing
   information.

**Expected Results**:
- Loki query by `trace_id` returns at least one log entry from
  the vLLM component
- Each returned entry is valid JSON conforming to the OTel Logs
  Data Model
- All required resource attributes (`service.name`,
  `k8s.pod.name`, `k8s.namespace.name`) are present and non-empty
- The `trace_id` value in the log entries matches the injected
  traceparent value
- Log entries are queryable within 60 seconds of emission
