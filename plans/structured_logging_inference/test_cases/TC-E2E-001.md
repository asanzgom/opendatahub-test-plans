# TC-E2E-001: Active inference request logs reach Loki

**Objective**: Verify best-effort forwarding of native request-time stdout/stderr from
vLLM, EPP, and MaaS to Loki (AC #1).

**Preconditions**:

- On a dedicated RHOAI inference cluster, the Monitoring CR has logging enabled and a
  healthy admin-installed Loki backend; the collection path selected by sprint-zero is active.
- vLLM, EPP, and MaaS request paths each produce a recognizable *native* request-time log
  entry. Record the actual namespace, workload pod, request route and log pattern for each.
- Resolve the Monitoring CR field and Loki query mechanism from the shipped design before
  running; neither is specified in the strategy. Use a synthetic namespace-scoped query identity.

**Test Steps**:

1. For each of vLLM completions, EPP dispatch, and MaaS proxy handling, record the pod's
   log position and UTC start time, send a synthetic inference request, and record end time.
2. Confirm each request was processed by its deployed inference path; inspect pod stdout/stderr
   to identify a native log line produced during request processing, not at initialization.
3. Query Loki through Console Observe > Logs as the authorized tenant, scoped to that
   workload namespace, pod and request window. Match the native request log line;
   do not require JSON or `trace_id`.
4. Repeat for the second namespace to exclude a false positive from another workload.

**Expected Results**:

- Each processing path produces a native request-time entry in container stdout/stderr and
  the corresponding namespace-scoped Loki query contains that entry from the same pod.
- Collection is best effort; this test does not demand one-to-one event counts or latency SLAs.
- If a given build emits no identifiable native request-time entry, record a test blocker rather
  than synthesizing a new logging-format requirement.
