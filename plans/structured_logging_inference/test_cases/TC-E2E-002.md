# TC-E2E-002: Missing Loki dependency surfaces status without stopping inference

**Objective**: Verify that a missing logging backend is identified on the Monitoring CR
while inference requests continue (AC #2, Dependency Resilience NFR).

**Preconditions**:

- Dedicated test cluster with a working vLLM inference workload and a healthy logging baseline.
- Operator-approved, reversible procedure for making the admin-installed Loki backend absent;
  record the selected dependency, Monitoring CR reference, and recovery procedure. Do not
  uninstall shared infrastructure or affect another user's workloads.
- Monitoring CR condition type/reason schema is obtained from the implementation contract.

**Test Steps**:

1. Record Monitoring CR conditions and execute a baseline inference request successfully.
2. Apply the approved missing-Loki procedure and trigger/observe Monitoring CR reconciliation.
3. Inspect conditions on the Monitoring CR, including reason/message identifying the missing
   dependency. Do not assert an invented `LoggingReady` condition name.
4. Send another inference request and inspect its response and workload availability.
5. Restore Loki using the approved procedure and confirm reconciliation recovers.

**Expected Results**:

- Monitoring CR status identifies the missing Loki backend as the logging dependency issue.
- Inference remains available and the request completes despite the logging failure.
- The cluster can be returned to its healthy baseline without changing inference workloads.
