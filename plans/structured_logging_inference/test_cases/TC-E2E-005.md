# TC-E2E-005: Controller reconciliation logs stay outside request collection

**Objective**: Confirm background controller lifecycle entries do not enter the
inference-request collection results (AC #5).

**Preconditions**:

- Logging enabled for an inference namespace with a healthy Loki backend and an authorized
  query identity. Identify a controller pod outside the request workload and its native
  reconciliation log pattern; do not require modifying the controller formatter.

**Test Steps**:

1. Record UTC time and log positions of the controller and vLLM/EPP request workload pods.
2. Trigger a safe controller reconciliation and an inference request in the same bounded
   time window. Confirm a reconciliation line in the controller pod logs and a request-time
   line in the inference pod logs; otherwise record an inconclusive run.
3. Inspect the deployed collection selectors/inputs to confirm the controller pod and
   namespace are not selected by the inference-request collection pipeline.
4. In Console Observe > Logs, confirm the request entry is present in the inference
   namespace. Query Loki using an authorized operator identity across the pipeline's
   full output (not just the inference namespace) for the controller pod and native
   message. If full output is unavailable, record an inconclusive exclusion result
   rather than treating the narrow query as proof.

**Expected Results**:

- Request-time log entry appears in the targeted Loki result.
- Neither the inference collection selectors nor their full output include the confirmed
  controller reconciliation entry produced during that request window.
