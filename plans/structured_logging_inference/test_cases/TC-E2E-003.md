# TC-E2E-003: Collection pipeline lifecycle and dependency surfacing

**Objective**: Validate that the odh-observability controller
creates logging collection resources when enabled, removes them
when disabled, and surfaces clear status conditions when
dependencies are missing.

**Preconditions**:
- OpenShift 4.16+ cluster with RHOAI 3.6 deployed
- odh-observability controller running
- Monitoring CR accessible
- LokiStack NOT deployed initially

**Test Steps**:
1. Verify the Monitoring CR does not have logging enabled and no
   logging collection resources exist:
   ```bash
   oc get monitoring -n redhat-ods-applications -o yaml
   ```
2. Enable logging in the Monitoring CR (apply logging subsection
   configuration).
3. Wait for the odh-observability controller to reconcile (up to
   60 seconds).
4. Verify the Monitoring CR status includes a condition indicating
   that the Loki backend is not installed, with an installation
   documentation reference:
   ```bash
   oc get monitoring -n redhat-ods-applications \
     -o jsonpath='{.status.conditions}' | jq .
   ```
5. Deploy LokiStack via the Loki Operator.
6. Wait for the controller to reconcile again.
7. Verify logging collection resources are created with correct
   input selectors (inference namespaces) and output configuration
   (Loki endpoint):
   ```bash
   # Check for collection resources (OTel or CLO depending on path)
   oc get otelcol,clusterlogforwarder -A
   ```
8. Disable logging in the Monitoring CR.
9. Wait for reconciliation.
10. Verify logging collection resources are removed (AC 9).

**Expected Results**:
- With logging enabled but Loki missing: Monitoring CR status
  condition identifies missing Loki dependency with documentation
  reference
- With logging enabled and Loki deployed: collection resources
  exist with correct namespace selectors and Loki output config
- With logging disabled: no logging collection resources exist
- Inference workloads (if deployed) continue to operate normally
  throughout all state transitions
