# TC-E2E-004: Namespace-scoped Loki queries cannot cross tenant boundaries

**Objective**: Confirm Tenant A cannot see Tenant B's request logs and vice versa (AC #4).

**Preconditions**:

- Logging enabled with healthy Loki, and distinct inference namespaces `qe-log-a` and
  `qe-log-b`, each with a working request path and synthetic tenant identity.
- Resolve Loki query credentials, actual tenancy mapping, authorized query mechanism and
  namespace RBAC from the design. Never use an unrestricted cluster-admin identity for
  the negative queries.

**Test Steps**:

1. Send requests in each namespace; identify one native request-time log entry per tenant
   from its pod and bounded UTC window. Do not rely on prompts containing real secrets.
2. In Console Observe > Logs as Tenant A, query A's request entries and then attempt to
   query B's namespace/window.
3. In Console Observe > Logs as Tenant B, query B's request entries and then attempt to
   query A's namespace/window.
4. Cross-check the two own-namespace results are non-empty before trusting negative results.

**Expected Results**:

- Each tenant can find its own request log; the opposite tenant's log is absent or the
  cross-namespace query is denied in both directions.
- A successful empty query alone is not accepted unless the other tenant's own query
  positively demonstrates its log was ingested.
