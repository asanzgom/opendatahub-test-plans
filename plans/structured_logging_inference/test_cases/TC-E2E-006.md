# TC-E2E-006: Unreachable collection dependency does not block deployment

**Objective**: Verify an unreachable logging backend or selected collector is reported
without blocking model deployment or inference (AC #2, Dependency Resilience NFR).

**Preconditions**:

- Dedicated cluster with healthy baseline and a documented, reversible fault injection
  for the *selected* logging path. Identify a synthetic model deployment that can be
  created without disrupting shared workloads.
- Obtain actual Monitoring CR condition type/reason from implementation contract.

**Test Steps**:

1. Record baseline dependency status and complete a baseline inference request.
2. Make the selected logging backend or collector unreachable without removing model
   runtime networking; trigger/observe Monitoring CR reconciliation.
3. Inspect Monitoring CR status for a condition identifying that dependency failure.
4. Deploy a synthetic model, wait for its normal readiness indication, and send an
   inference request to it. Restore the logging dependency and verify health recovery.

**Expected Results**:

- Monitoring CR reports the specific unreachable logging dependency.
- The model deployment becomes ready and its inference request completes while logging
  is unavailable; restoring the logging dependency clears the failure state.
